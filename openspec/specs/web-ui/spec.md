## Purpose

Встроенный веб‑интерфейс агента — единственный UI проекта: работает везде, где работает контейнер (Mac, NAS), покрывает весь поток настройки и наблюдения без нативного приложения.

## Requirements

### Requirement: UI is served by the agent on the API port
Агент SHALL отдавать веб‑интерфейс (SPA) на том же HTTP‑порту, что и API `/v1`. Все ресурсы SHALL быть встроены в бинарь агента; страница MUST NOT загружать что‑либо с внешних адресов (CDN, шрифты) — UI работает без доступа контейнера в интернет.

#### Scenario: Open UI
- **WHEN** пользователь открывает `http://<хост>:<порт>/` в браузере
- **THEN** загружается интерфейс Detour без обращений к сторонним доменам

#### Scenario: Tunnel down does not affect UI
- **WHEN** VPN отключён и uplink недоступен
- **THEN** UI открывается и показывает состояние (интерфейс не зависит от туннеля)

### Requirement: Admin password and sessions
При первом открытии (пароль ещё не задан) UI SHALL предлагать задать пароль администратора; хэш SHALL храниться в томе. Далее доступ к UI SHALL требовать входа по паролю; сессия — HTTP‑only cookie; выход — по кнопке. Запросы, меняющие состояние, SHALL быть защищены от CSRF. После 5 неверных паролей подряд SHALL действовать пауза не менее 30 секунд.

#### Scenario: First run
- **WHEN** пользователь открывает UI на свежем томе
- **THEN** единственная доступная страница — создание пароля; после создания начинается онбординг

#### Scenario: Unauthenticated access
- **WHEN** запрос к любой странице или `/v1`‑ресурсу приходит без валидной сессии или Bearer‑токена
- **THEN** страница перенаправляется на вход, API отвечает `401`

#### Scenario: Password change
- **WHEN** пользователь меняет пароль в настройках
- **THEN** прочие активные сессии становятся недействительными

### Requirement: Dashboard
Главная страница SHALL показывать: состояние подключения (значок‑индикатор, локация, `protocol.requested`/`effective` с причиной, публичный IP, длительность), кнопку Подключить/Отключить, выбор локации (поиск, Smart, избранные, недавние), состояние uplink'а с переключением `host`/`socks5`, блок адреса прокси с действием «Скопировать» (адрес показывается таким, каким он достижим с точки зрения клиента: хост из URL браузера + опубликованный SOCKS5‑порт), сводку последнего self‑check с кнопкой запуска. Изменения состояния SHALL отображаться без перезагрузки страницы не позднее чем через 1 секунду (SSE `/v1/events`).

#### Scenario: Connect from dashboard
- **WHEN** пользователь выбирает локацию и нажимает «Подключить»
- **THEN** статус проходит «подключается → подключён» без перезагрузки страницы

#### Scenario: Proxy address on NAS
- **WHEN** UI открыт по адресу `http://nas.local:48100`
- **THEN** блок прокси показывает `socks5://nas.local:1080` (хост из адресной строки, опубликованный порт)

### Requirement: Settings pages
UI SHALL предоставлять разделы: **ExpressVPN** (аккаунт: вход по коду активации/выход; протокол; защита; автоподключение), **Uplink** (режим, параметры SOCKS5, UDP `auto/on/off`, кнопка «Проверить» с результатами), **Proxy** (аутентификация входящего SOCKS5, статистика), **Container** (read‑only обзор: контейнер, образ и версии, том, порты — с командами compose), **Access** (смена пароля администратора, «выйти на всех устройствах», просмотр/ротация API‑токена, язык интерфейса, уведомления), **Diagnostics** (self‑check, логи). «Живые» изменения SHALL применяться сразу с видимым результатом (применено/ошибка по полю).

#### Scenario: Live protocol change
- **WHEN** пользователь переключает протокол
- **THEN** рядом с полем появляется подтверждение «применено» без перезагрузки, `GET /v1/config` отражает новое значение

### Requirement: Recreate-scoped parameters are read-only in UI
Параметры, требующие пересоздания контейнера (порты на хосте, адрес привязки, версия ExpressVPN/образа), SHALL отображаться в UI как текст, а не как элементы форм: никаких полей ввода, попапов и переключателей — ничто в интерфейсе MUST NOT выглядеть редактируемым, если UI не может это применить. Рядом со значением SHALL быть пометка «edit in .env» и доступная инструкция (имя переменной + копируемая команда `docker compose up -d --build`). UI MUST NOT предлагать применить их сам.

#### Scenario: Change host port
- **WHEN** пользователь открывает параметр «порт SOCKS5 на хосте»
- **THEN** значение показано текстом (не полем ввода) с пометкой «edit in .env», рядом — имя переменной и команда compose для применения

### Requirement: First-run onboarding
После создания пароля на свежем томе UI SHALL вести пользователя по шагам: вход в ExpressVPN (код активации; код не пишется в логи и не отображается после ввода) → первое подключение (выбор локации или Smart) → подсказка, как прописать прокси в приложениях. Шаги с ошибками SHALL показывать причину и оставлять возможность повторить.

#### Scenario: Fresh volume onboarding
- **WHEN** контейнер поднят на пустом томе и пароль создан
- **THEN** UI показывает шаг входа в ExpressVPN; после успешного входа — шаг первого подключения; после подключения — dashboard

### Requirement: Diagnostics in UI
Раздел диагностики SHALL показывать результаты self‑check (IP через прокси, IP uplink'а, DNS, вердикт с причинами), живой поток логов с фильтром по компоненту и скачивание диагностического архива; архив MUST NOT содержать код активации, пароли, хэши и токены.

#### Scenario: Live log tail
- **WHEN** пользователь открывает логи с фильтром `uplink`
- **THEN** новые записи uplink'а появляются в реальном времени

### Requirement: Connection notifications
UI SHALL уметь отправлять браузерные уведомления (Web Notifications, по явному разрешению пользователя, переключатель в Access, по умолчанию выключено) при исчерпании автопереподключения (`reconnect_exhausted`) и при падении uplink'а.

#### Scenario: Reconnect exhausted notification
- **WHEN** уведомления включены и агент сообщает `connection=error` с `reconnect_exhausted`
- **THEN** браузер показывает уведомление с причиной; клик открывает Dashboard

### Requirement: Localization and responsiveness
UI SHALL поставляться с английской и русской локализациями (по языку браузера, с ручным переключением) и SHALL оставаться работоспособным на экранах от 360px ширины (администрирование с телефона).

#### Scenario: Mobile layout
- **WHEN** UI открыт в окне шириной 390px
- **THEN** dashboard и настройки доступны без горизонтальной прокрутки
