## MODIFIED Requirements

### Requirement: Admin password and sessions
При первом открытии (пароль ещё не задавался) UI SHALL предлагать задать пароль администратора; хэш SHALL храниться в томе. Далее доступ к UI SHALL требовать входа по паролю; сессия — HTTP‑only cookie; выход — по кнопке. Запросы, меняющие состояние, SHALL быть защищены от CSRF. После 5 неверных паролей подряд SHALL действовать пауза не менее 30 секунд.

Защиту паролем SHALL быть возможно выключить: пропустить создание пароля на первом шаге онбординга или снять уже установленный пароль в Settings → Access (с подтверждением текущим паролем). При выключенной защите UI SHALL открываться сразу без входа; элементы, связанные с сессиями («Sign out», «выйти на всех устройствах»), MUST NOT отображаться; в Access SHALL отображаться заметное предупреждение, что страница открыта для всех, у кого есть сетевой доступ, вместе с действием «установить пароль». Включение пароля обратно SHALL применяться сразу, без пересоздания контейнера.

#### Scenario: First run
- **WHEN** пользователь открывает UI на свежем томе
- **THEN** единственная доступная страница — создание пароля (с возможностью пропустить); после создания или пропуска начинается онбординг

#### Scenario: Unauthenticated access
- **WHEN** защита включена и запрос к любой странице или `/v1`‑ресурсу приходит без валидной сессии или Bearer‑токена
- **THEN** страница перенаправляется на вход, API отвечает `401`

#### Scenario: Password change
- **WHEN** пользователь меняет пароль в настройках
- **THEN** прочие активные сессии становятся недействительными

#### Scenario: Open UI while protection is off
- **WHEN** защита паролем выключена и пользователь открывает UI
- **THEN** UI открывается сразу без экрана входа; кнопка «Sign out» отсутствует; в Access виден предупреждающий баннер с действием «установить пароль»

#### Scenario: Turn protection off from Access
- **WHEN** пароль задан и пользователь в Settings → Access выключает защиту, подтверждая текущим паролем
- **THEN** защита выключается сразу; UI остаётся открытым без сессии; неверный текущий пароль показывает ошибку и ничего не меняет

#### Scenario: Set a password after it was skipped
- **WHEN** защита выключена и пользователь в Settings → Access устанавливает пароль
- **THEN** защита включается сразу; открытые в других браузерах страницы при следующем запросе попадают на экран входа

### Requirement: Settings pages
UI SHALL предоставлять разделы: **ExpressVPN** (аккаунт: вход по коду активации/выход; протокол; защита; автоподключение), **Uplink** (режим, параметры SOCKS5, UDP `auto/on/off`, кнопка «Проверить» с результатами), **Proxy** (аутентификация входящего SOCKS5, статистика), **Container** (read‑only обзор: контейнер, образ и версии, том, порты — с командами compose), **Access** (смена пароля администратора, выключение/включение защиты паролем, «выйти на всех устройствах», просмотр/ротация API‑токена, язык интерфейса, уведомления; при выключенной защите — предупреждение и пометка у API‑токена, что он не требуется), **Diagnostics** (self‑check, логи). «Живые» изменения SHALL применяться сразу с видимым результатом (применено/ошибка по полю).

#### Scenario: Live protocol change
- **WHEN** пользователь переключает протокол
- **THEN** рядом с полем появляется подтверждение «применено» без перезагрузки, `GET /v1/config` отражает новое значение

#### Scenario: Access page reflects disabled protection
- **WHEN** защита паролем выключена и пользователь открывает Settings → Access
- **THEN** строка пароля показывает состояние «выключено» с действием «установить пароль»; строки сессий нет; у API‑токена — пометка, что при выключенной защите он не требуется

### Requirement: First-run onboarding
Первый шаг онбординга на свежем томе — создание пароля администратора — SHALL допускать пропуск («продолжить без пароля») с видимым предупреждением о последствиях: любой, кто может открыть страницу, управляет VPN и его настройками. После создания или пропуска пароля UI SHALL вести пользователя по шагам: вход в ExpressVPN (код активации; код не пишется в логи и не отображается после ввода) → первое подключение (выбор локации или Smart) → подсказка, как прописать прокси в приложениях. Шаги с ошибками SHALL показывать причину и оставлять возможность повторить.

#### Scenario: Fresh volume onboarding
- **WHEN** контейнер поднят на пустом томе и пароль создан
- **THEN** UI показывает шаг входа в ExpressVPN; после успешного входа — шаг первого подключения; после подключения — dashboard

#### Scenario: Onboarding continues after skipping the password
- **WHEN** контейнер поднят на пустом томе и пользователь выбирает «продолжить без пароля»
- **THEN** онбординг переходит к шагу входа в ExpressVPN, не требуя пароль и не прерываясь
