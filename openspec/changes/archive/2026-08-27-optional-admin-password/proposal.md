# Optional admin password

## Why

При развёртывании в доверенной домашней сети (единственный пользователь, доступ к странице есть только у владельца) обязательный пароль администратора — лишний барьер: его приходится придумывать, хранить и вводить. Нужна возможность пропустить создание пароля при первом запуске и снять уже установленный пароль — с возможностью в любой момент включить защиту обратно, без пересоздания контейнера.

## What Changes

- Состояние аутентификации становится тройственным: `unset` (свежий том — предлагается setup), `set` (вход по паролю) и `disabled` (защита сознательно выключена — UI и API открыты). Сегодня «нет файла пароля» неотличимо от «свежий том».
- Шаг «Создать пароль администратора» в онбординге можно пропустить («Continue without password»); остальные шаги онбординга идут как обычно.
- В Settings → Access появляется выключение пароля (с подтверждением текущим паролем) и обратное включение (форма «Set password»), когда защита выключена.
- При выключенной защите все `/v1`-запросы проходят без cookie-сессии и Bearer-токена, но мутирующие запросы защищаются проверкой `Origin`/`Sec-Fetch-Site` от cross-site запросов из браузера (fetch no-cors с чужих страниц). Не-браузерные клиенты (curl, скрипты) не шлют `Origin` и работают без изменений.
- UI честно отражает состояние «защита выключена»: предупреждающий баннер в Access, подпись у API-токена («не требуется»), скрытые «Sign out» и «Sessions» (сессий нет).
- CLI `detour-agent reset-password` сохраняет текущую семантику: возврат в `unset` (снова предлагается setup).

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `agent-api`: требование «Authenticated HTTP endpoint» — аутентификация обходится, когда защита паролем выключена (с Origin-проверкой мутирующих запросов); требование «Auth endpoints» — новые переходы состояний (skip при setup, disable, повторный setup после disable) и третье состояние в `/v1/auth/status`.
- `web-ui`: требование «Admin password and sessions» — состояние «защита выключена» и вход в UI без логина; «First-run onboarding» — пропускаемый шаг пароля; «Settings pages» — управление выключением/включением пароля в Access и честное отображение выключенной защиты.

## Impact

- **Агент (Go)**: `internal/api/sessions.go` (маркер состояния disabled рядом с файлом пароля), `internal/api/auth_handlers.go` (skip/disable/status), `internal/api/server.go` (`authorized()` + Origin-проверка мутирующих запросов), тесты `auth_test.go`.
- **Web UI (Svelte)**: `App.svelte` (третье состояние при загрузке, скрытие Sign out), `pages/Setup.svelte` (пропуск шага 1), `pages/settings/Access.svelte` (turn off / set password, баннер), `lib/i18n.js` (строки en/ru).
- **Спеки**: `openspec/specs/agent-api/spec.md`, `openspec/specs/web-ui/spec.md`.
- **Дизайн**: артборды уже обновлены в `design/expressvpn-sidecar-design.pen` (10b — skippable setup, 5b — Turn off, 5c — Access при выключенной защите).
- **Совместимость**: существующие развёртывания не затрагиваются (пароль остаётся установленным); API `/v1/auth/status` расширяется новым полем, старые поля сохраняют смысл.
