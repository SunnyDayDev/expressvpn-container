# S1 — установка ExpressVPN `.run` в arm64‑контейнере

Дата: 2026-08-25. Инсталлятор: `expressvpn-linux-universal-14.2.0.13656_release.run`
(SHA‑256 `9d770edc6548a17994fd15714c5030a8f5767671b76b2117a884f7d48d93f2cb`; сервер отдаёт
эталонные суммы в заголовках `x-amz-meta-sha256`/`x-amz-meta-md5`). База: `debian:trixie-slim`,
Docker Desktop / Apple Silicon.

## Вердикт: работает нативно (arm64), но контейнеру нужен ещё и `SYS_PTRACE`

`getconf PAGESIZE` = **4096**, `uname -m` = `aarch64` — требование «4K page size» выполняется.

## Что за инсталлятор

Makeself 2.5.0‑архив, внутри — `multi_arch_installer.sh`, диспетчеризующий в
`{arm64,x64}/install.sh` по `uname -m`. Клиент 14.x собран из кодовой базы PIA Desktop
(`pia_desktop` в метаданных сборки). Состав `…files/bin`: `expressvpn-daemon`,
`expressvpnctl`, `expressvpn-lightway(-rs)`, `expressvpn-openvpn`, `expressvpn-amneziawg-go`,
`expressvpn-unbound` (локальный DNS‑резолвер), `expressvpn-ss-local`, GUI‑клиент и пр.

## Команда установки (в Dockerfile)

```sh
sh installer.run --accept --quiet --nox11 --noprogress -- --no-gui --force-dependencies
```

- `--no-gui` — headless, GUI‑пакеты не ставятся.
- `--force-dependencies` — пропускает `checkContainerPrivileges` (при сборке нет
  NET_ADMIN/`/dev/net/tun` — проверка иначе валит установку) и `checkRuntimeDependencies`.
  Сами зависимости ставим заранее (см. ниже), `installDependencies` внутри инсталлятора
  затем находит их через `apt-get install -y` (нужен `apt-get update` до запуска).
- **`--sysvinit` не передаём.** Автодетект в контейнере уходит в systemd → `systemctl`
  отсутствует → `BOOT_MANAGER=none`: файлы ставятся, сервис не настраивается и не
  запускается (запуск сервиса при сборке невозможен и уронил бы `set -e`).
  `/etc/init.d/expressvpn-service` в образе, соответственно, нет — и не нужен.

Зависимости (apt): `bash ca-certificates iproute2 iptables procps psmisc libatomic1
libbrotli1 libnl-3-200 libnl-route-3-200 libglib2.0-0` (+`libcap2-bin` для setcap
`expressvpn-unbound`, опционально).

## Пути

| Что | Где |
|---|---|
| Установка | `/opt/expressvpn/{bin,lib,share}` |
| Настройки демона + сессия входа | `/opt/expressvpn/etc/` (`account.json`, `data.json`, `settings.json`, `api_client`, `csdk`) |
| Рантайм‑состояние | `/opt/expressvpn/var/` (`daemon.sock`, `crashes/`, `daemon.log` при debug) |
| CLI | `/opt/expressvpn/bin/expressvpnctl`, симлинк `/usr/local/bin/expressvpnctl` |

Для тома: персистировать **`/opt/expressvpn/etc`** (вход в аккаунт, настройки).
`/opt/expressvpn/var` — рантайм (сокет, логи), персистировать не нужно.

## Запуск демона

Без init‑систем, напрямую (так же делает systemd‑юнит):

```sh
LD_LIBRARY_PATH=/opt/expressvpn/lib /opt/expressvpn/bin/expressvpn-daemon
```

- Стоп‑сигнал — **SIGINT** (из sysvinit‑скрипта: `STOP_SIGNAL=INT`).
- Готовность: `expressvpnctl -t 60 get connectionstate` → `Disconnected` (~5–8 с после старта).
- Агент супервизирует демон как прямой дочерний процесс — init‑скрипты не используются
  (решение обновлено относительно ранней версии design.md, где упоминался sysvinit).
- Отладка: файл `/opt/expressvpn/var/.expressvpn-early-debug` включает трассировку в
  `/opt/expressvpn/var/daemon.log` (механизм `$HOME/.expressvpn-early-debug` из install.sh).

## Ключевая находка: `CAP_SYS_PTRACE` обязателен

Демон авторизует IPC‑клиентов на `daemon.sock`, читая путь бинаря подключившегося
процесса (`/proc/<pid>/exe`). В контейнере без `SYS_PTRACE` readlink чужого
`/proc/<pid>/exe` даёт `EACCES` — в `daemon.log`:

```
[src/ipc.cpp:208][error] Failed to retrieve client process binary path (code: 13) Permission denied
[src/ipc.cpp:274][warning] Rejected client connection from ""
[src/ipc.cpp:294][info] Unauthorized client connection, will ignore.
```

— и **все** команды `expressvpnctl` молча таймаутятся (rc=2). С `--cap-add SYS_PTRACE`
всё работает. Требование добавлено в compose (`cap_add: [NET_ADMIN, SYS_PTRACE]`) и в
проверку прав агента при старте.

## Прочее

- Демон при старте сразу ходит в API ExpressVPN (JSON‑конфиги, QR) — из региона
  пользователя это работает только при доступном uplink'е (S2/S4); на инициализацию IPC
  не влияет: ctl отвечает и без сети.
- `status` до входа: `Not logged in.` + `Network Lock: enabled when connected` (по
  умолчанию!) + `Split Tunnel: disabled` → при старте выключаем Network Lock (см. спеку
  kill-switch).
- Установка занимает ~4 с в сборке; образ спайка ~0.9 ГБ.
